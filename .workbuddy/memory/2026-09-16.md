## A股区间预测学习平台 — 可行性评估（首轮）

用户提出产品构想：A股历史数据学习平台，用户选股 → 系统智能识别若干区间 → 用户选区间 →
基于区间信息预测买入/卖出/持有 → 类似模拟炒股但用历史数据学习。请求先评估可行性。

### 已给出的评估结论
- 技术可行性高（个人自用场景），主要难点不在技术，而在①产品定义 ②合规边界。
- 拆出核心七步闭环：选股 → 区间识别 → 用户选题 → 屏蔽未来 → 给出判断 → 真实结算 → 评分反馈。
- 定位出最大技术陷阱：**前视偏差（look-ahead bias）**，即"屏蔽未来"这一步做不彻底，
  产品会退化成看图说话，是该产品成败的关键。
- 技术架构五层：数据采集 / 数据存储 / 计算引擎（自研重点）/ 服务接口 / 前端界面。
- 技术选型建议：AkShare + Baostock（取数据）、DuckDB/Parquet（存储）、FastAPI（服务）、
  React + ECharts（前端 K 线）、自研轻量回测结算（不必上 Backtrader/vnpy）。
- 提醒的工程脏活：前/后复权、涨跌停无法成交、停牌、除权除息、ST/新股/退市、幸存者偏差。
- 合规红线：免费数据接口不可商用；对外提供具体买卖建议涉及证券投资咨询牌照，
  个人学习自用风险低，公开运营收费风险显著上升。
- 评分设计建议：区分运气与能力，样本不足 100 次不展示胜率。

### 绘制了 3 个可视化
1. 七步核心学习闭环（HTML 交互 stepper）
2. 区间切分与决策点示意（SVG 时间轴：可见区 / 隐藏结算区 / 决策点）
3. 技术架构五层（SVG 分层图）

## A股学习平台 — 第二轮：决策基线定稿

用户逐条回复了上轮的待定问题，产出 `docs/00-设计决策基线.md`（v0.1）。

### 已拍板的 13 项决策
1. 软件名：**温故**（备选 重演 / 覆盘 / 知往），目录名 `wengu`
2. 区间定义：**混合方案** —— 算法负责"切"（边界可复现、零成本），
   AI 负责"选 + 说"（从候选池挑题、写题目描述）。AI 不参与边界计算。
3. 预测模式：用户自答为主 + 判卷模式（评判模型预测）为辅
4. 结算：默认值 + 用户可自定义；算法算数字，AI 只做归因解读
5. 交易成本：佣金万2.5最低5元 / 印花税0.05%卖出单边 / 过户费0.001%双向
   / 规费0.0541‰ 双向 / 滑点 0.05%（均已联网核实为 2026 现行标准）
6. 评分：不判成功失败，输出策略收益、标的收益、基准（沪深300）收益、
   超额收益、**机会成本**、最大回撤、全程持有对照
7. 数据源：Baostock 为主（免费/无流量限制/含退市股完整历史），AkShare 补充
8. 存储：**DuckDB + Parquet**（约 4000 万行日线，压缩后 300~800MB，单机足够）
9. 前视偏差：后端强制 mask，AI 侧同样隔离（输入脱敏、不含真实日期与股票名）
10. 复权：存「不复权价 + 复权因子」；展示用前复权，算收益用后复权
11. 不可成交：完整处理 T+1 / 涨跌停（按板块区分幅度）/ 停牌 / 新股前5日 / ST
12. 幸存者偏差：全历史保留退市股 + 构造 point-in-time 时点标的池
13. 合规：仅个人自用，不考虑

### 本轮新增的技术要点（值得记住）
- **模型侧前视偏差**：即使不给 AI 未来数据，模型训练语料里可能已包含该段行情，
  会不自觉泄题。缓解办法是数据脱敏 + 限定 AI 只做排序叙述。
- **技术指标本身可能带未来信息**：滚动指标必须严格用"截止当日"窗口，
  不能在全历史上做归一化。这是极易忽略的隐性泄题。
- **空仓刷分漏洞**：若不记录机会成本，用户"一直选卖出"在熊市里永远跑赢沪深300。
  必须用「机会成本 + 超额收益」配对约束。
- Baostock 数据盘后更新、无实时行情，但本项目是历史学习平台，无需实时。

### 绘制了 4 个可视化
1. 混合方案 vs 纯算法 vs 纯 AI 三方案对比（HTML 卡片）
2. 不复权 / 前复权 / 后复权价格曲线对比（含除权跳空标注）
3. 幸存者偏差两种标的池对比图
4. （上轮）七步学习闭环 stepper、区间切分决策点、技术架构五层

## 第三轮：新增「知识随行」模块（技术知识学习）

用户需求：在预测过程中能学到技术分析知识（K 线形态、量价关系等），且**支持关闭/开启**。
已写入 `docs/00-设计决策基线.md` 第 12 节，决策速览表新增第 14 行。

### 我识别出的核心矛盾
**在作答前给提示 = 泄题。**「当前是早晨之星形态」这句话本身就等于告诉用户该买。
所以知识模块不能做成侧边挂个知识面板，必须按**时机**切分。

### 三阶段设计（核心）
| 阶段 | 定位 | 给什么 | 绝不给什么 |
|---|---|---|---|
| 作答前 | 教方法，不指方向 | 知识点卡片（定义/识别特征/含义）+ 3~5 个候选知识点 | 不说哪个真的出现；不标注当前 K 线 |
| 作答中 | 给工具，不给结论 | 可叠加均线/成交量/MACD；区间统计摘要 | 不自动提示「MACD 金叉」；不自动标注形态 |
| 作答后 | 揭晓 + 归因 | 真实形态高亮标注、量价画像、AI 解读、实证胜率 | 无（答案已揭晓） |

### 三个关键设计点
1. **防泄题：知识点配平**。展示集 = 真实 1~2 个 + 干扰项 2~3 个。
   两条硬约束：数量配平（真实项 ≤ 总数 1/3）、**方向配平**（看涨/看跌/中性数量相等）。
   方向不配平的话，用户数一数"看涨的比看跌多"就能蒙对方向，练习就废了。
2. **`detect_rule` 字段是支点**。只有形态能被算法量化识别，才能做到：
   作答后精确揭晓 / 作答前构造配平干扰项 / 长期统计真实胜率。
   不可量化的（如道氏理论）标 `detect_rule = null`，只入知识库不参与自动匹配。
3. **杀手锏：用自己的数据统计形态真实胜率**。手上就有全 A 股 30 年数据，
   可对每个形态做全样本回测（出现次数 / 上涨概率 / 平均收益 / 跑赢沪深300 概率）。
   三条纪律：用全样本（不用用户练过的题）、**必须含退市股**、必须标注样本量
   （不足 100 次标"数据不足"，不展示胜率）。

### 开关设计：三级，不是一个总开关
总开关（模块开/关）→ 阶段开关（前/中/后独立）→ 模式预设（一键切换）。
四种模式：学习模式（全开）/ 考试模式（前关后开）/ 纯净模式（全关）/ 速查模式（只翻知识库）。

### 最容易漏掉但影响最大的一点
**开关状态必须计入作答快照**（`fact_answer.knowledge_mode`）。
开着提示答对 vs 裸考答对，说服力完全不同，**成绩必须分账统计**，不能混算胜率。
再配合"学习模式下随机抽 10~20% 的题关闭全部提示且不提前告知"，
用来持续跟踪"离开提示后的真实水平"，并防止用户为好看成绩而永不开提示。

### 知识库结构
`dim_knowledge`：name / alias / category / definition / **detect_rule** /
signal_direction / position / meaning / pitfalls / diagram / related
分类：单根K线 / K线组合 / 趋势与结构 / 量价关系 / 均线系统 / 技术指标

### 绘制可视化
知识随行三阶段对比（HTML 三卡片，标注"提供"与"禁止"）

## 第五轮：知识模块重大修订 + 产出 MRD

### 用户拍板的修订（改变模块定位）
> **作答前不展示知识点；作答后匹配到就弹出给用户巩固记忆；
> 一个区间可以有多个相同知识点，不人为限制成"一个区间只保留一个同类"。**

## 第七轮：新增「时间回放模式」+ 解决 N1

### 用户需求（原话要点）
> 分时买入时可以自动推进分时，也可以用户点按键手动推进（**不可后退，只能前进**），
> 每次推进一分钟之类的。**软件的初衷是把时间推回到某一天，让用户在那一天去买入股票**，
> 用户可以自己推进时间。要支持**单股票训练**（练买入时机）和**全部股票训练**（练盘感）。
> 尽可能接近真实市场，支持把时间回退到某一天然后从那一天开始炒股。
> 结束时间可以提前设置，也可以不设置一直玩下去。

**这是产品定位的大升级**：从「单模式（区间判断）」变成「**双模式**」。

### 双模式对照（已写入文档）

| | 判断模式 | 回放模式 |
|---|---|---|
| 时间形态 | 一次性给一段区间 | 逐格推进，像真实看盘 |
| 交互 | 三选一 | 买/卖/加仓/减仓 |
| 仓位 | 无（虚拟） | **有真实仓位** |
| 结果 | 单次收益 + 机会成本 | 账户净值曲线 |
| 训练目标 | 单次决策质量 | 买入时机、仓位管理、盘感 |

**意外收获**：判断模式的老痛点——「买入/持有/卖出」在无仓位下语义重叠
（持有和卖出都等于不建仓）——在回放模式里因有真实仓位而**自然消解**。

### 五条硬约束（核心设计）
1. **只能前进不能后退** —— 服务端只给 `advance(n)`，**不给** `set_time(t)`。能后退=能反悔=模式失效。
2. **粒度默认 5 分钟** —— 因为 **Baostock 有 5 分钟线（1999-07-26 至今）但没有 1 分钟线**。
3. **成交价用下一格** —— 第 N 格下单用第 N+1 格成交。
   用当格收盘价成交等于让用户"买在最低点"，这是**分钟级的前视偏差**（新发现的陷阱）。
4. **可见性边界同判断模式** —— 只返回 `dt <= current_dt`。
5. **单股票零预处理** —— 一只票 10 年分钟数据仅约 12 万行，即时加载；
   只有全股票模式才需要预下载（10 年约 7.2 亿行）。

### ✅ N1 已解决（重要，且推翻了原决策）
查阅 Baostock 官方说明得到确切入库时间：
- **日 K 线：当日 17:30 入库**
- **分钟 K 线：当日 20:30 入库**
- 财务数据：次日 1:30

**→ 用户原定的 16:00 同步是错的，16:00 时当日数据根本还没入库。**
已把同步时间**修正为 21:00**（00 号第 11 节 + 01 号 B4 + 非功能需求 + 路线图 M0）。
原"需要连续观察几天"的待办**不必再做了**。

### 本轮查到的其他硬事实
- Baostock 分钟线粒度：**5/15/30/60**，历史可追溯到 **1999-07-26**（极深）
- Baostock **无 1 分钟**数据；**指数没有分钟线**（所以回放模式里沪深300 基准只能用日线）
- AkShare 有 1 分钟接口，但分钟级数据**只返回有限区间、非全量**，历史深度浅
- 数据量：5 分钟线全 A 股 10 年约 **7.2 亿行 / 压缩后 4~7 GB**；
  存储预算从原来的 <1 GB 涨到 **8~10 GB**

## 第九轮：判断模式改为真实仓位 + 修正全部评审问题

### 用户新需求（改变了产品核心交互）
> **"判断模式也要有真实仓位，不要只做单纯的涨跌判断，要有买入、卖出操作"**

**这个要求顺带解决了评审发现的问题 B1**——原来"持有"和"卖出"在无仓位下
执行结果完全一样（都是不建仓、收益都是 0%），只是名字不同，一直没解释清。
**有了真实仓位，"持有"和"卖出"成为完全不同的动作，歧义自动消失。**

### 判断模式改造要点（已写入文档）

| 项 | 原设计 | 现在 |
|---|---|---|
| 决策方式 | 三选一（买/持/卖） | **真实下单**（买/卖 + 股数） |
| 快捷操作 | 无 | 空仓 / 半仓 / 全仓 / 清仓 |
| 题目初始状态 | 无（隐含空仓） | **空仓型** 或 **持仓型（N 股 @ 成本 Y）**，两种都要有 |
| 结算 | 策略收益率 | **账户视角**（总资产 = 现金 + 持仓市值） |
| 仓位管理 | 完全丢失 | **成为训练内容**（"买多少"本身要练） |

**持仓型题目的价值**：真实中你多数时候是**已有持仓**的，"该不该卖"往往比
"该不该买"更难。原设计只覆盖了空仓型。

### 两个模式的边界（重新定义）
**唯一区别是推进粒度**：
- 判断模式 = **一个决策点**（区间末），30 秒一题，题海式
- 回放模式 = **逐格推进**（5 分钟），数分钟到数小时，沉浸式

交易规则、成本模型、结算口径**完全一致**，且**共用同一个交易引擎**
（`TradeEngine`：下单/成交/持仓/现金/除权调整/净值）。

> 待确认 N13：判断模式是否允许在结算窗口内设多个决策点？
> 若允许，它就变成"日线粒度的回放模式"，两者边界会模糊。

### 评审 16 项全部处理

- **A1 复权口径** → 按模式拆分。回放模式**一律不复权**（原用前复权是错的：
  前复权基准是"最新价"，历史价被后续分红全部改写，与当天盘面不符）。
  另在 03 号文档新增 **8.3「除权除息处理」**——原设计**完全缺失**，
  不处理会在除权日凭空巨亏（送股让股数变、分红让现金多，引擎却不知道）。
- **A2 P0 泛滥** → 重定义优先级。**P0 由 57 条（67%）降至 29 条（30%）**；
  FR-5 / FR-9 / FR-10 三组整组不再设 P0。
- **A3 下载耗时** → 补入 **40~200 小时（2~8 天）**估算 + 断点续传设为必需功能。
- **A4 价值观冲突** → 7.2 指标全部中性化，删掉"过度保守/追高/杀跌"等形容词，

### 写进项目约定的教训（重要）

> 根因分析：机制变更时，人的注意力集中在"主叙述段落"（决策速览、功能定义），
