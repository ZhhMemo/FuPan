# 第一部分 · 产品

## 1. 产品概览

### 1.1 一句话定义

> **复盘**：用真实历史数据当考题、用真实行情当判卷的 A 股决策训练平台。
> **把时间推回过去，用真金白银下单，让市场告诉你结果。**

- 项目名：**复盘**（fù pán）
- 仓库/目录名：`fupan`
- 全称建议：**复盘 · A 股决策训练场**（单用两个字略通用，配副标题更明确）

### 1.2 这是什么 / 不是什么

划这条界线是为了**防止功能蔓延**——每加一个功能前，先问它是否越界。

| 这是 | 这不是 |
|---|---|
| 历史决策训练工具 | 荐股软件 / 投资顾问 |
| 认知偏差的照妖镜 | 模拟炒股比赛 |
| 技术分析知识的实证工具 | 行情看盘软件 |
| 个人知识管理系统 | 交易执行系统 / 自动下单 |
| 数据驱动的复盘工具 | 社交 / 排行榜产品 |

**明确不做的事**（写死，避免以后动摇）：

- ❌ 不接入实盘账户、不做自动交易
- ❌ 不提供针对当前市场的买卖建议
- ❌ 不做实时行情、不做盘中提醒
- ❌ 不判定用户的判断「成功」或「失败」

### 1.3 三条设计哲学（不可动摇）

| # | 原则 | 含义 |
|---|---|---|
| 1 | **只给过去，不给未来** | 用户能看到的只有决策点之前的数据。任何形式的前视污染都视为**产品缺陷**，不是「体验问题」 |
| 2 | **不判对错，只给事实** | 输出收益率、超额收益、机会成本、最大回撤，但绝不说「你判断错了」。**这条对学习档案同样成立**：只给数字与对照，不使用「过度保守 / 追高 / 杀跌」这类形容词 |
| 3 | **逼近真实成本** | 手续费、印花税、过户费、滑点、T+1、涨跌停无法成交、停牌，全部模拟。宁可结算结果难看，也不要一个「理论收益率」 |

> 第 2 条容易走偏。产品的职责是**把镜子擦亮**，不是告诉用户长得怎么样。
> 给事实和对照、不给结论——否则产品会变成另一种说教。

### 1.4 产品全貌

```
                    ┌─────────────────────────────────────┐
                    │           共 用 底 座                │
                    │  数据（日线 + 分钟线 + 复权因子）      │
                    │  交易引擎（下单/成交/持仓/成本/净值）   │
                    │  交易规则（T+1 / 涨跌停 / 停牌 / 除权） │
                    │  前视偏差防火墙 mask(dt ≤ 当前时刻)    │
                    │  知识点匹配引擎                       │
                    └──────────────┬──────────────────────┘
                                   │
                ┌──────────────────┴──────────────────┐
                │                                     │
        ┌───────▼────────┐                  ┌─────────▼─────────┐
        │   判断模式      │                  │    回放模式        │
        │  一个决策点     │                  │   逐格推进          │
        │  30 秒 / 题     │                  │   数分钟 ~ 数小时    │
        │  题海式快练     │                  │   沉浸式实战        │
        ├────────────────┤                  ├───────────────────┤
        │ 训练：单次决策  │                  │ 训练：买入时机      │
        │      仓位管理   │                  │      持仓管理       │
        │                │                  │      盘感           │
        └────────────────┘                  └───────────────────┘
```

**两个模式的唯一区别是推进粒度。** 交易规则、成本模型、结算口径完全一致，
且共用同一个交易引擎。这条的一致性红利是：判断模式里训练出的判断力，
能直接迁移到回放模式，不会出现「在 A 模式学到的经验在 B 模式不成立」。

## 2. 背景与问题

### 2.1 要解决的四个问题

| # | 问题 | 现状的痛点 |
|---|---|---|
| 1 | **看盘软件只讲「发生了什么」** | 打开软件能看到全部走势，无法回到「当时只知道这些」的状态，因此永远训练不到真实决策能力 |
| 2 | **模拟炒股周期太长、样本太少** | 用实时行情模拟，一个决策要等一个月才能验证；练 20 次要一年多，学不到东西 |
| 3 | **人肉复盘带着后见之明** | 自己翻历史 K 线时，眼睛已经看到了后面的走势，无法排除前视偏差，复盘结论不可靠 |
| 4 | **技术分析知识停留在术语层面** | 学了一堆形态名称，但从没验证过「这个形态在 A 股到底有没有用」 |

### 2.2 为什么现在可行

| 条件 | 说明 |
|---|---|
| **数据可得** | Baostock 免费提供全 A 股**含退市股**的完整历史日线（含复权因子）+ 5/15/30/60 分钟线（1999 年至今）。这是过去需要付费才能拿到的数据 |
| **算力足够** | 全历史日线约 4500 万行，压到 0.5 GB；分钟线 10 年约 7.2 亿行、4~7 GB。单台服务器完全 hold 得住，不需要任何分布式方案 |
| **无合规负担** | 仅个人学习自用，不对外发布、不收费、不提供投资建议 |

### 2.3 明确排除的做法

- ❌ 不做实时行情：本项目是历史训练，实时数据既贵又无用
- ❌ 不做移动端原生 App：先做 Web UI（浏览器访问，手机也能开但**不专门做移动适配**）
- ❌ 不做深度学习模型：数据量与验证成本都不划算，先用规则策略

## 3. 目标用户与场景

### 3.1 用户画像

| 维度 | 描述 |
|---|---|
| 身份 | 个人投资者 / 技术爱好者。本项目目前只有 1 位用户（产品作者本人） |
| 能力 | 会写代码，能自己动手改；懂基本交易规则；技术分析知其名不知其实证 |
| 约束 | 每天可投入 10~30 分钟；周末可投入 1~2 小时 |
| 设备 | **浏览器访问为主**（本地开发用 macOS；生产部署在 Linux 云服务器） |
| 痛点 | 缺乏结构化练习；没有客观反馈；技术知识无法验证 |

### 3.2 六个典型场景

| # | 场景 | 期望行为 | 成功标志 |
|---|---|---|---|
| S1 | **碎片时间刷题** | 打开浏览器做 3~5 道随机题 | 单题全流程 ≤ 2 分钟 |
| S2 | **周末系统性练习某个板块** | 按行业 / 板块筛选标的，连续练 20 道同类题 | 能按条件筛题并批量练习 |
| S3 | **验证一个技术形态** | 想确认「早晨之星到底有没有用」，直接查该知识点的全历史统计 | 能看到出现次数、上涨概率、样本量 |
| S4 | **看清自己的判断偏差** | 查学习档案：什么行情下判断得准、什么时候总是错、仓位习惯如何 | 按区间类型看到仓位分布与账户收益 |
| S5 | **单股票回放** | 盯住一只票，把时间推回某天，逐格推进琢磨买入时机 | 能完成一次跨多日的完整交易并复盘 |
| S6 | **全股票回放练盘感** | 回到某天，在几千只票里现场找机会 | 能从全市场快照中筛选并下单 |

### 3.3 使用节奏

- 日常：每天 3~10 题（判断模式，碎片时间）
- 深度：每周 1 次 20~50 题，或 1 次 30 分钟以上的回放会话
- 查询：需要时随时翻知识库与统计

## 4. 产品目标与衡量

### 4.1 北极星指标

> **累计完成的「有效练习」数量**（同一题重复练习只计首次）

选它而不是「收益率」的理由：本产品是学习工具，衡量的是**练习量与练习质量**，
不是赚钱能力。用收益率当指标会诱导用户去追高风险题目，方向就歪了。

**关于重复练习的定位**（一个容易含糊的点）：

| 类型 | 是否计入北极星 | 说明 |
|---|---|---|
| 首次练习 | ✅ 计入 | 有效样本，进入学习档案统计 |
| 重复练习 | ❌ 不计入 | **但允许做，且完整记录**。用途是「复习」，不进成绩分母 |

两类记录都不删除。重复练习的价值是**巩固**，不是刷成绩——
因此重新作答同一道题**不会提升任何统计指标**，从机制上避免自我刷分。

### 4.2 阶段性目标

| 阶段 | 目标 | 可验证的完成标志 |
|---|---|---|
| M1 后 | 闭环跑通，能独立做完一道题 | 能登录、在决策点**实际下单**、看到结算与账户结果 |
| M2 后 | 题目池有货，能连续练习 | 题目池 ≥ 10 万道，可随机抽题 |
| M3 后 | 每次练习都有知识巩固 | 下单后能自动匹配并展示知识点 |
| M4 后 | 能看见自己的进步与偏差 | 学习档案按区间类型给出仓位分布与账户收益 |
| M5 后 | 能把时间推回去连续交易 | 单股票模式可用；能恢复会话并出复盘报告 |

### 4.3 明确不追求的指标

- 不追求收益率最大化（这是训练工具，不是策略）
- 不追求用户数、留存、活跃（个人自用）
- 不追求形态识别覆盖率 100%（批次 1 的 30 种就够启动）

## 5. 核心概念与术语表

| 术语 | 定义 |
|---|---|
| **区间** | 一段连续的历史行情，有明确的起止日期。用户要在这段区间末做出决策 |
| **决策点（T）** | 区间的最后一个交易日。用户只能看到 T 及之前的数据 |
| **结算窗口** | 决策点之后的验证期，默认 20 个交易日 |
| **题目（Question）** | 一道练习的最小单位 = 股票 + 区间 + 类型标签 + **初始持仓** + 结算参数 |
| **题目初始状态** | 每道题指定的起始持仓：**空仓型** 或 **持仓型（N 股 @ 成本 Y）** |
| **判卷模式** | 系统给出仓位建议，用户评判建议对不对（判断模式的辅助分支） |
| **下单** | 用户的实际交易操作：买入 / 卖出 + 股数（取代原来的三选一判断） |
| **持仓** | 当前持有的股票与成本。**有持仓时，「持有」与「卖出」才成为不同动作** |
| **仓位** | 持仓市值 ÷ 总资产。**仓位大小本身就是本产品的训练内容之一** |
| **交易引擎** | 两个模式共用的下单 / 成交 / 持仓 / 现金 / 除权调整 / 净值计算模块 |
| **机会成本** | 标的实际收益 − 账户收益。衡量「错过了多少 / 躲过了多少」 |
| **超额收益** | 账户收益 − 基准（沪深300）收益 |
| **时点标的池** | 回答「那一天在市的股票有哪些」，而非「今天在市的股票」 |
| **快照冻结** | 结算时锁定当时的复权因子与费率，保证历史成绩日后不被改写 |
| **时间回放模式** | 把时间推回某一天、逐格推进并真实买卖的训练模式 |
| **推进粒度** | 回放模式每次前进的时间长度，默认 5 分钟 |
| **训练会话** | 一次回放训练从开始到结束的完整过程（资金、持仓、交易记录、当前时刻） |
| **净值曲线** | 回放模式下总资产随时间的变化，是该模式的结果呈现 |
| **盘感** | 全股票模式训练的目标：在几千只票中快速识别机会的能力 |
| **知识点命中** | 算法在区间内检测到某个技术形态出现（同一知识点可多次命中） |
| **显著性分** | 知识点命中的可信程度打分，用于分层展示 |
| **技术工具** | 观察时可叠加的指标：均线、成交量、MACD、KDJ、BOLL |

# 第二部分 · 玩法

## 6. 双模式架构

### 6.1 两个模式对照

| | **判断模式** | **回放模式** |
|---|---|---|
| 决策点数量 | **一个**（区间末） | 每推进一格都可决策 |
| 推进粒度 | 整个区间 | 5 分钟（可配 1/5/15/30/60） |
| 观察方式 | 一次性看到整段 K 线 | 逐格推进，像真实看盘 |
| 单次耗时 | 30 秒 | 数分钟到数小时 |
| 定位 | 题海式快练 | 沉浸式实战 |
| 结果呈现 | 结算页（账户视角） | 净值曲线 + 复盘报告 |
| 训练目标 | 单次决策质量、仓位管理 | 买入时机、持仓管理、盘感 |
| 数据需求 | 日线 | **分钟线** |

### 6.2 为什么是这两种

它们覆盖了决策训练的两个层次：

- **判断模式**解决「广度」：用 30 秒一题的速度，在几百上千个不同行情里反复练习，
  建立条件反射式的判断框架。
- **回放模式**解决「深度」：在一个真实推进的场景里，体会**等待、犹豫、持有、
  加仓、止损**这些只有连续时间流逝才能产生的心理过程。

判断模式练不到的，正是回放模式的价值所在。

### 6.3 共用底座

```
TradeEngine（交易引擎）
├── 下单(order)          买 / 卖 + 股数
├── 成交撮合(fill)       按规则取价、检查涨跌停与停牌、扣除全部成本
├── 持仓维护(position)   shares / available_shares / avg_cost
├── 现金维护(cash)       卖出回款、买入扣款、分红入账
├── 除权调整(adjust)     送股调股数、分红入现金
└── 净值计算(nav)        总资产 = 现金 + 持仓市值
```

**调用方式不同，引擎本身不变**：

| 模式 | 调用方式 |
|---|---|
| 判断模式 | **单次调用**（在决策点执行下单） |
| 回放模式 | **循环调用**（每推进一格都可下单） |

这是整个产品最重要的结构性决策：**不会出现「两个模式各写一套交易逻辑、
结果收益率口径不一致」的问题**。

## 7. 判断模式详解

### 7.1 七步主流程

| 步 | 环节 | 说明 |
|---|---|---|
| 1 | **选股** | 从时点标的池中选一只（或系统随机） |
| 2 | **出题** | 系统从题目池切出若干候选区间供选择 |
| 3 | **选题** | 选定一个区间作为本次考题 |
| 4 | **观察** | 界面**只显示决策点之前的数据**；可叠加技术工具 |
| 5 | **下单** | **实际买入 / 卖出操作**（含股数与快捷仓位按钮） |
| 6 | **结算** | 按决策点之后的真实行情计算**账户结果**与各项指标 |
| 7 | **知识复盘** | 匹配本区间出现的知识点并弹出，供巩固记忆 |

### 7.2 题目有两种初始状态

| 题型 | 初始状态 | 训练什么 |
|---|---|---|
| **空仓型** | 现金 100%，无持仓 | 「这个位置该不该进场、进多少」 |
| **持仓型** | 已持有 N 股、成本 Y | 「该加仓、减仓、清仓，还是不动」 |

**为什么持仓型更重要**：真实交易中你绝大多数时间是**已有持仓**的。
「该不该卖」往往比「该不该买」更难。只做空仓型等于漏掉了更难的那一半。

两种题型按比例混合（初始五五开），题目上打标签，便于分开统计。

> **待定（N14）**：持仓型题目的初始成本怎么定？
> 用区间起点价格？还是刻意构造成「已浮亏 15%」这类有教学价值的状态？
> 后者更能考出决策质量。

### 7.3 下单交互

| 操作 | 说明 |
|---|---|
| 买入 | 指定股数或金额 |
| 卖出 | 指定股数（不超过可卖数量） |
| 不动 | 有仓位即「持有」，无仓位即「观望」 |
| 快捷按钮 | 空仓 / 半仓 / 全仓 / 清仓 |

**「买多少」本身就是训练内容**——仓位管理是原三选一设计完全丢失的维度。

> **待定（N15）**：一键全仓是不可逆的大动作，是否需要二次确认？

### 7.4 结算与结果呈现

**结算语义**：从决策点 T 的下一个交易日开盘价成交（含滑点），
持有到结算窗口结束，按后复权价计算账户结果。

**输出指标（不判对错，只给事实）**：

| 指标 | 含义 |
|---|---|
| 账户收益率 | (期末总资产 − 初始总资产) / 初始总资产，含全部成本 |
| 标的收益率 | 该股票在结算窗口的实际涨跌 |
| 基准收益率 | 沪深300 同期 |
| 超额收益 | 账户收益率 − 基准收益率 |
| **机会成本** | 标的收益率 − 账户收益率（错过了多少 / 躲过了多少） |
| 最大回撤 | 持有期间的最深浮亏 |
| 全程持有对照 | 若决策点买入并持有到底的收益 |

> ⚠️ **「机会成本」必须与「超额收益」配对出现**。
> 否则用户会发现「只要一直不买，大盘跌的时候我的收益率就是 0%，
> 永远跑赢沪深300」，然后学会一个完全错误的策略。

**快照冻结（FR-4.6）**：结算时锁定当时的复权因子与费率版本。
复权因子会随新的分红除权重算，不冻结的话，**三个月前那笔练习的收益率
今天重算会变**，用户翻历史成绩时会发现对不上。

### 7.5 判卷模式（分支）

在步骤 5 前插入一步：系统给出**仓位建议**（如「建议加仓至 60%」），
用户评判这个建议对不对，再走结算。

它的价值是对新用户友好：不需要自己先有观点，只需要会评判。

### 7.6 异常流程

| 异常 | 处理 |
|---|---|
| 区间内该股停牌 | 结算时跳过停牌日，按复牌首日可成交价处理 |
| 结算窗口内该股退市 | 按退市整理期最后成交价强制平仓，并在结算页标记该题 |
| 决策点次日一字涨停（无法买入） | 顺延到下一个可成交日；窗口内始终无法成交则标记「未成交」 |
| 决策点次日一字跌停（无法卖出） | 同上，顺延 |
| 数据缺失 / 交易日历异常 | 该题作废，不进入题目池 |
| 结算窗口不足 20 个交易日 | 该题暂不出题 |

## 8. 时间回放模式详解

> 完整规范见 `03-时间回放模式设计.md`，本节是可读版概要。

### 8.1 核心定位

> 用户原话：**「把时间推回到某一天，让用户在那一天去买入股票，用户可以自己去推进时间。」**

### 8.2 推进机制

| 方式 | 行为 | 用途 |
|---|---|---|
| **自动推进** | 按固定间隔自动跳格，可暂停、可调速 | 像看盘，感受时间流逝的节奏 |
| **手动推进** | 按一次前进一格 | 仔细琢磨，慢慢想 |

两者可随时切换。

**铁律：只能前进，不能后退。** 这是整个模式成立的根基——
能后退就等于能反悔，练习立刻失去意义。三层保险：

1. 服务端**只提供** `advance(n)`，**不提供** `set_time(t)`
2. 服务端持有 `current_dt`，前端无法指定或修改
3. 所有数据接口一律只返回 `dt <= current_dt` 的数据

**推进粒度：默认 5 分钟，可配 1/5/15/30/60。** 这里有个数据层的硬约束：

| 粒度 | 数据可得性 |
|---|---|
| 5 / 15 / 30 / 60 分钟 | Baostock 提供，**1999-07-26 至今**，历史极深 ✅ |
| **1 分钟** | Baostock **不提供**；AkShare 有接口但**历史深度很浅** ⚠️ |

> 5 分钟粒度对「训练买入时机」其实够用——真实散户也很少按分钟盯盘。

**一日之内的推进序列**（5 分钟粒度，一天 48 格）：

```
09:35 → 09:40 → …… → 11:30      上午 24 格
            ↓ 跳过午休
13:05 → 13:10 → …… → 15:00      下午 24 格
            ↓ 跳到下一交易日
次日 09:35 → ……
```

停牌日整体跳过。

### 8.3 可见性边界

| 可见 | 说明 |
|---|---|
| 当前时刻**之前**的全部历史 | 日线、分钟线都能看。真实看盘软件也这样，不构成泄题 |
| **当日开盘 → 当前时刻**的分时 | 就像真实看盘 |
| 当前时刻的全市场行情快照 | 全股票模式下的选股依据 |

| 绝对不可见 |
|---|
| 当前时刻**之后**的任何数据（当日剩余分时、之后所有交易日） |
| 任何形式的「边界延伸」：均线画到当前时刻之后、提示「即将涨停」之类 |

### 8.4 ⚠️ 分钟级成交的前视陷阱

**在「当前格」还没走完时下单，成交价不能用当前格的收盘价。**

推进到第 N 格结束时，用户看到的是这一格的完整 OHLC——
但真实交易中，你在这一格之内下单，不可能预知这一格的收盘价。

> **规则：在第 N 格下单，用第 N+1 格的成交价成交。**

这与判断模式的「T+1 开盘价成交」是同一逻辑，只是粒度从「日」变成「格」。
用错的话，用户会获得「买在当格最低点」的不真实优势。

### 8.5 涨跌停与 T+1 的分钟级实现

| 规则 | 实现 |
|---|---|
| **T+1** | 当日买入的股数记为「不可卖」，次日解锁 |
| **卖出后可再买** | A 股 T+1 只限制「卖当日买入的」，卖出后当天可以再买 |
| **一字涨停** | 该格 `high == low == 涨停价` → 禁止买入 |
| **一字跌停** | 同理 → 禁止卖出 |
| **停牌** | 该日无分钟数据，推进时整体跳过 |

### 8.6 除权除息处理（原设计缺失，已补）

回放模式用**不复权价**（真实盘面口径），所以必须自己处理除权除息——
否则持仓跨越除权日时，**净值会凭空暴跌**。

| 情况 | 正确处理 |
|---|---|
| **送股 / 转增**（10 送 3） | 股数 × 1.3，`avg_cost` 按比例下调；现金不变 |
| **现金分红**（10 派 5 元） | 现金 += 股数 × 0.5；股数不变 |
| **配股** | 需用户决定是否参与（默认不参与，并标记） |
| **红利税** | 按持股期限差别化征收。**MVP 可先按 0 处理并标注简化** |

处理时机：**在推进跨过除权日的那一刻自动执行**，并在会话日志里记一笔可查的调整记录。

### 8.7 单股票 vs 全股票

| 模式 | 数据范围 | 训练什么 | 数据预处理 |
|---|---|---|---|
| **单股票** | 一只票 | 买入时机、加减仓、持仓管理 | **无需预处理**，选定后即时加载（10 年约 12 万行） |
| **全股票** | 全市场 | 选股、盘感、板块轮动 | **必须预下载**（10 年约 7.2 亿行） |

**全市场分钟数据的下载是一个「天」级任务**：约 **40 ~ 200 小时（2 ~ 8 天）**，
且中断在所难免。因此**断点续传是必需功能，不是可选项**。

> 这个划分的实用价值：**单股票模式可以立刻开发与使用**，不必等这 2~8 天。
> 所以 M5 分两步上线。

### 8.8 结束条件与会话

| 方式 | 说明 |
|---|---|
| **预设结束日** | 到期自动结束并出报告 |
| **不设结束** | 一直玩到数据末尾；也可主动结束 |

用户中途关掉浏览器要能接着玩，因此会话必须持久化：

```
sim_session     session_id, mode(single/multi), code, start_date, end_date,
                granularity, current_dt, cash, status, created_at
sim_position    session_id, code, shares, available_shares, avg_cost
sim_trade       trade_id, session_id, dt, code, side, price, shares, fee_detail, cash_after
sim_nav         session_id, date, total_asset, cash, market_value
```

`available_shares` 与 `shares` 分开存，是 T+1 的实现方式——这个字段拆分别省。

### 8.9 结果输出

回放模式**不需要「结算」**——账户净值曲线本身就是结果。

| 输出 | 说明 |
|---|---|
| 净值曲线 | 总资产随时间变化 |
| 累计 / 年化收益 | |
| 最大回撤 | |
| 对比沪深300 | 同期基准与超额收益 |
| 交易明细 | 每笔买卖的时间、价格、费用、盈亏 |
| 交易统计 | 次数、胜率、平均持仓天数、盈亏比 |

## 9. 知识复盘模块

### 9.1 定位

> **作答前不展示任何知识点；作答后，当算法匹配出本区间出现过的知识点时，
> 自动弹出供巩固记忆。**

这是**结果复盘式教学**：先让你独立判断，再告诉你刚才那段行情里其实发生了什么。

**一个意外收益**：这个设计让泄题风险归零、实现反而更简单——
原方案曾在作答前展示候选知识点，为了防用户「数一数看涨的比看跌的多」就蒙对方向，
不得不加「方向配平」补丁。现在作答前什么都不给，**配平机制整节作废**。

### 9.2 三阶段边界（不可越）

| 阶段 | 定位 | 提供 | 禁止 |
|---|---|---|---|
| **作答前** | 什么都不给 | 无 | **界面不出现任何知识点**、任何形态标注、任何信号提示 |
| **作答中** | 给工具，不给结论 | 默认开启的技术工具：均线、成交量、MACD、KDJ、BOLL；区间统计摘要 | 不自动提示指标信号；不自动标注形态；**指标线不得延伸到决策点之后** |
| **作答后** | 揭晓 + 巩固 | 本区间匹配到的**全部**知识点（分层展示）；K 线图上高亮每次出现的位置；量价画像；全历史实证统计 | 无（答案已揭晓） |

> 为什么作答中可以开放技术工具：均线 / MACD / KDJ / BOLL 全部由**历史数据**算出，
> 本身不含未来信息，不构成泄题。前提是**严格截断在决策点**。

### 9.3 匹配引擎

统一抽象：

```
Detector.detect(ohlcv_slice) -> List[Occurrence]
Occurrence = { kb_id, start_idx, end_idx, confidence, detail }
```

按 `detect_type` 分两路，对应形态的两种本质：

| 类型 | 适用知识点 | 检测方式 |
|---|---|---|
| **point**（点状） | 单根 K 线、K 线组合、部分指标信号 | 逐根滑窗，以候选点为中心取固定回溯窗口。局部计算，天然无前视 |
| **persistent**（持续） | 趋势结构、量价背离、均线排列、指标状态 | 在整段区间做序列 / 状态计算，返回「成立区间」而非单点 |

### 9.4 一个知识点出现多次怎么处理

**不人为限制成一个区间只保留一个同类知识点，按实际情况来。**

| 层 | 处理 |
|---|---|
| **数据层** | **存多条**，一次出现一条。不合并计数——每次出现的位置、显著性分、上下文都不同 |
| **展示层** | 按知识点聚合，标注「出现 N 次」；每次出现分别高亮；可展开查看逐次明细 |

例：区间内出现 3 次早晨之星 → 卡片显示「早晨之星 ×3」，展开后列出第 12 / 34 / 56 日
及各自显著性分。

### 9.5 显著性打分（分层展示的依据）

一个震荡区间可能命中 30 个以上知识点，全平铺会淹没用户。
所以**数据层全部保留、不设数量上限，展示层收敛**。

```
score = Σ(权重 × 特征)

strictness          命中条件数 / 条件总数     判定越严格越可信
confirmation        决策点前的确认度          形态在决策点前被验证的程度
position            距决策点的距离            越近越相关
duration            持续天数                  对 persistent 类生效
direction_clarity   方向明确度                非中性加分
```

展示规则：按 score 降序，**默认展开前约 40%**，其余收进「查看全部」按类别分组。
**不设数量硬上限**——有多少展示多少，只是默认收起。

> ⚠️ **硬约束**：`confirmation` 必须使用**决策点之前的确认度**。
> 若写成「形态被后续 K 线确认」，窗口一旦越过决策点就是前视偏差。

### 9.6 杀手锏：全历史实证统计

这是我们相对教科书的**独有优势**——手上就有全 A 股 30 年数据：

> **早晨之星** · 历史出现 12,847 次
> 之后 20 个交易日：上涨概率 54.2%，平均收益 +1.3%，中位数 +0.6%，
> 跑赢沪深300 的概率 51.1%

这能直接回答「这个形态到底有没有用」，把技术分析从玄学变成可验证的命题。

**三条统计纪律**：① 用**全样本**（不能用用户练过的题）；
② **必须含退市股**（否则又是幸存者偏差）；③ **必须标样本量**——
不足 100 次的标「数据不足」，不展示胜率。

### 9.7 开关设计

| 层级 | 控制内容 |
|---|---|
| **总开关** | 知识复盘模块 开 / 关 |
| **子开关** | 作答后知识点提示 开 / 关 |
| **模式预设** | 学习模式（全开，默认） / 纯净模式（全关） |

另外保留一个**速查入口**：不进练习、直接翻知识库，按分类浏览与搜索。

### 9.8 开关状态只用于学习统计，不再做成绩分账

原设计要求按开关状态分账统计成绩。修订后**降级**——
因为作答前本来就不给任何提示，**开关不影响作答难度**，没有分账的必要。

改为：仍记录开关状态，但用途变成**学习行为统计**（如「复盘查看率」）。

## 10. 学习档案

### 10.1 设计目标

**呈现事实与对照，让用户自己看出模式**——而不是替用户下结论。

### 10.2 指标定义

| 指标 | 定义 | 呈现方式 |
|---|---|---|
| 累计有效练习数 | 按模式 / 区间类型分组计数，重复练习只计首次 | 数字 |
| 平均仓位 | 每笔练习的平均仓位比，按区间类型分组 | 数字 |
| **仓位方向匹配度** | 上涨区间的平均仓位 − 下跌区间的平均仓位 | **两个数字并列**，差值仅作参考 |
| 账户收益率 | 账户视角收益率（含全部成本） | 数字 |
| 相对沪深300 收益 | 账户收益率 − 沪深300 同期收益 | 数字 |
| **机会成本** | 标的收益 − 账户收益 | **必须与上一行配对展示** |
| 最大回撤 | 持有期间最深浮亏 | 数字 |
| 交易频率 | 平均每笔练习的下单次数 | 数字 |
| **持仓型题目的选择分布** | 加仓 / 不动 / 减仓 / 清仓 各占多少 | **四个比例并列** |
| 各类行情下的仓位分布 | 上涨 / 下跌 / 震荡 区间的平均仓位 | 三个数字并列 |
| 知识复盘查看率 | 下单后查看知识点的比例 | 数字 |
| 知识点学习效果 | 看过某知识点后，同类题目的表现变化 | 数字 |

### 10.3 呈现原则（三条）

1. **不出现形容词。** 「空仓比例 62%」是事实，「过度保守」是评判——只给前者。
2. **必须给对照。** 单独一个 62% 没有意义，要和「同期标的上行概率 51%」并列才有意义。
3. **让用户自己下结论。** 产品的职责是把镜子擦亮，不是告诉用户长得怎么样。

> 这些才是本产品的差异化价值。收益率谁都能算，
> **能照出你自己的行为模式**，才是训练工具的意义。

# 第三部分 · 引擎与数据

## 11. 交易引擎

### 11.1 职责

交易引擎是整个产品的**核心共用件**，两个模式都通过它完成交易。

| 职责 | 说明 |
|---|---|
| 下单 | 接收买单 / 卖单，校验资金、持仓、T+1 可卖数量 |
| 成交撮合 | 按模式规则取成交价；检查涨跌停与停牌；扣除全部成本 |
| 持仓维护 | `shares` / `available_shares` / `avg_cost` |
| 现金维护 | 卖出回款、买入扣款、分红入账 |
| 除权调整 | 送股调股数、分红入现金（仅回放模式需要） |
| 净值计算 | 总资产 = 现金 + 持仓市值 |

### 11.2 成交规则

| 项 | 判断模式 | 回放模式 |
|---|---|---|
| 成交时点 | T+1 日**开盘价** | 下单的**下一格**价格 |
| 滑点 | 双向各 0.05% | 双向各 0.05% |
| 无法成交 | 顺延到下一个可成交日 | 顺延到下一格 |
| 价格口径 | 后复权（算收益） | **不复权**（真实盘面） |

### 11.3 成本模型（2026 年现行标准）

| 项目 | 费率 | 收取方式 |
|---|---|---|
| **佣金** | 万分之 2.5，最低 5 元 | 双向（全佣，含规费） |
| **印花税** | **0.05%** | **仅卖出单边** |
| **过户费** | 0.001% | 双向，沪深统一 |
| **规费** | 经手费 0.0341‰ + 证管费 0.02‰ = 0.0541‰ | 双向（含在全佣内） |
| **滑点** | 0.05% | 双向，可配 0 ~ 0.5% |

> ⚠️ 费率会随政策调整，**应做成可配置参数而非硬编码**。
> 印花税 0.05% 为 2023 年 8 月起减半后的标准，过户费 0.001% 为 2022 年 4 月起沪深统一标准。

### 11.4 涨跌停与 T+1

| 规则 | 实现 |
|---|---|
| **T+1** | 当日买入的股数记为「不可卖」，次日解锁；卖出后可当日再买 |
| **一字涨停** | 当日 `最高价 == 最低价 == 涨停价` → 禁止买入，顺延 |
| **一字跌停** | 同理 → 禁止卖出，顺延 |
| **开盘即封板** | `开盘价 == 涨停价` → 视为无法买入（保守规则，可配开关） |
| **停牌** | 停牌期间禁止交易，顺延至复牌首日 |
| **涨跌幅比例** | 主板 ±10%、创业板 / 科创板 ±20%、北交所 ±30%，按板块分别计算 |
| **价格精度** | 涨跌停价四舍五入到分，与真实规则一致 |
| **新股前 5 日** | 注册制股票前 5 日无涨跌幅限制。**直接从标的池剔除上市不足 60 个交易日的股票**，回避复杂度 |

### 11.5 结算默认参数

| 参数 | 默认值 | 可选范围 |
|---|---|---|
| 决策点 T | 区间最后一个交易日 | — |
| 成交时点 | T+1 日**开盘价** | 可选 T+1 收盘价 / T 日收盘价 |
| 结算窗口 | **20 个交易日** | 5 / 10 / 20 / 60 / 120 / 自定义 |
| 平仓时点 | 第 20 个交易日收盘价 | 可选 |
| 初始资金 | **10 万元** | 自定义（两个模式统一） |
| 基准指数 | **沪深300（000300）** | 可加：上证、创业板指、中证500 |
| 滑点 | 双向各 **0.05%** | 自定义 0 ~ 0.5% |

## 12. 数据体系

### 12.1 数据源选型

| 数据源 | 用途 | 理由 |
|---|---|---|
| **Baostock**（主） | 日线、分钟线、复权因子、交易日历、指数 | 免费无需积分、无流量限制、历史极深、**含退市股** |
| **AkShare**（补充） | 财务数据、公告、板块、龙虎榜 | 接口极丰富，但属爬虫、易失效，**只做按需补充** |
| Tushare（备用） | 校验、兜底 | 免费积分档够用 |
| 巨潮资讯（后期） | 公告财报原文 | 基本面题目的素材来源 |

**关于 AkShare**：它是爬虫，接口会随上游网站改版失效，
**绝不能用它做 7×24 的定时任务**。

**关于分钟级数据**：

| 粒度 | 来源 | 历史范围 |
|---|---|---|
| 5 / 15 / 30 / 60 分钟 | **Baostock** | **1999-07-26 至今** |
| 1 分钟 | Baostock **无**；AkShare 有但历史深度浅 | ⚠️ 只能做近日训练 |

> **指数没有分钟级数据**，所以回放模式里的沪深300 基准只能用日线。

### 12.2 更新时间与同步策略

| 数据 | Baostock 入库时间 |
|---|---|
| 日 K 线 | 当日 **17:30** |
| 分钟 K 线 | 当日 **20:30** |
| 财务数据 | 次日 1:30 |

**同步时间定为每日 21:00**（在全部数据入库之后）+ 支持手动触发。

> ⚠️ 这条修正过一次：原定 16:00，但那时当日数据根本还没入库，
> 同步会拉不到当天数据，而且**看起来还像是成功了**。
> 另需注意**服务器时区**——必须显式指定北京时间，否则服务器若为 UTC 会错 8 小时。

**同步要求**：断点续传 + 每日失败清单重试 + **每日同步后自动健康检查**
（股票数突变 / 日期跳跃 / 价格非负非零 / 涨跌幅超限）。

### 12.3 复权口径（按模式区分，很重要）

| 场景 | 用什么价 | 为什么 |
|---|---|---|
| **判断模式 · 展示** | 前复权 | 用户心理预期是「价格和同花顺一致」，量级也对得上 |
| **判断模式 · 计算** | 后复权 | 分红送股后股数变了，不复权算出的收益率是错的 |
| **回放模式 · 展示与成交** | **不复权** | 回放是把时间推回某一天，用户看到的必须是**当时的真实报价**。前复权基准是「最新价」，历史价会被后续分红全部改写，与当天盘面对不上 |
| **回放模式 · 收益** | **不复权价 + 现金分红流水** | 回放里有真实持仓，分红应作为**现金入账**、送股应**调整股数** |

**存储只存一套**：不复权 OHLCV + 复权因子，各种口径都能现算。
两个原因：① 省空间且永不失真；② **前复权与后复权的历史都会变**——
新的除权会改变全部历史价格，落库即错，必须实时计算。

## 13. 知识点库建设

### 13.1 三条原则

| 原则 | 含义 | 违反会怎样 |
|---|---|---|
| **知识点是数据，不是代码** | `detect_rule` 用 JSON DSL 描述，新增知识点 = 插一行数据 | 每加一个形态都要改代码、测代码、发版，半年后引擎变成一堆 if-else |
| **引擎只认原语** | 引擎实现一组通用特征与算子；表达不了的新形态 → **扩展原语**，不给单个知识点开特例 | 引擎腐化，规则越加越乱 |
| **每条规则必须可验证** | 有客观判定标准（命中率区间 + 抽样肉眼核对） | 规则写完没人知道对不对，统计全是噪声 |

### 13.2 `detect_rule` DSL

规则**不写公式**，只做「读取预定义特征 → 比较 → 组合」。
所有计算（均线、量比、相关系数…）都由引擎预计算成特征列，规则只引用特征名。

**特征原语（部分）**：

| 类别 | 示例 |
|---|---|
| 单根 K 线 | `body_ratio`（实体 / 振幅）、`upper_shadow_ratio`、`direction`、`is_limit_up`、`volume_ratio` |
| 序列特征 | `ma(n)`、`close_vs_ma(n)`、`highest(n)`、`position_in_range(n)`、`volatility(n)`、`corr_price_volume(n)` |

**算子**：比较（`> >= < <= == !=`）、区间（`between`）、
引用其他根（`value_ref: "close@-3"`）、逻辑组合（`all_of` / `any_of` / `none_of`）、
计数（`count_of`）。

**示例：早晨之星（point 型）**

```json
{
  "kb_id": "kc_morning_star",
  "detect_type": "point",
  "window_size": 3,
  "anchor": -1,
  "conditions": {
    "all_of": [
      { "field": "direction",  "bar": -3, "op": "==", "value": "down" },
      { "field": "body_ratio", "bar": -3, "op": "<=", "value": 0.5 },
      { "field": "body_ratio", "bar": -2, "op": "<=", "value": 0.3 },
      { "field": "low",        "bar": -2, "op": "<",  "value_ref": "low@-3" },
      { "field": "direction",  "bar": -1, "op": "==", "value": "up" },
      { "field": "close",      "bar": -1, "op": ">",  "value_ref": "close@-3" }
    ]
  },
  "signal_direction": "bullish"
}
```

### 13.4 质量双关卡（规则验收）

写规则最怕「看着像」就上线。每条规则必须过两关：

| 日命中率 | 判断 | 处理 |
|---|---|---|

| **0.5% ~ 5%** | ✅ 合理 | 通过 |
| < 0.1% | 太严，样本不足 | 放宽条件 |
| = 0 | 规则写错了 | 排查特征或逻辑 |

**第二关：抽样肉眼核对** —— 随机抽 10 个命中样本，确认符合教科书定义。

> 两关缺一不可。命中率只是数量指标，**不保证质量**。

## 14. 质量红线（不可妥协的 5 条）

这五条是本项目区别于「看起来像那么回事」的关键。
**每条都给判定方法**——只写要求不算数。

| # | 红线 | 要求 | **怎么验证做对了** |
|---|---|---|---|
| 1 | **前视偏差** | 用户与 AI 在任何环节都拿不到决策点之后的数据 | ①抓包检查下单接口，返回数据 `max(date) ≤ end_date`；②指标曲线末点日期 ≤ 决策点；③下单前界面无任何知识点；④回放模式只能看 `dt ≤ 当前时刻` |
| 2 | **价格口径** | 判断模式：展示前复权、计算后复权。回放模式：展示与成交**一律不复权** | ①取一只多次分红的银行股，判断模式手工核对收益率，应与不复权算法**不相等**且差异方向合理；②回放模式跨除权日时**净值不出现凭空暴跌**，股数与现金按送股 / 分红正确调整 |
| 3 | **成交可行性** | 无法成交的情况必须真实反映 | 找一只真实一字板股票，验证该日买入被拒绝并正确顺延 |
| 4 | **幸存者偏差** | 标的池含退市股，按「当时在市」过滤 | ①数据库中能查到已知退市股的历史；②指定一个历史日期，标的池中**不含**该日尚未上市的股票 |
| 5 | **结果可复现** | 历史成绩不因数据更新被改写 | 记录一笔结算结果，更新复权因子后重算，**数字必须完全一致**（依赖结算快照冻结） |

**三条容易被当成「细节」而漏掉的实现约束**：

1. **屏蔽未来必须做在后端。** 前端「不渲染」等于没做——数据已经在客户端了。
2. **指标线必须截断在决策点。** 均线 / MACD / BOLL 由历史数据算出、本身不泄题，
   但绝不允许把线画到决策点之后，哪怕只是一段延伸线。
3. **滚动指标只能用「截止当日」窗口。** 禁止全历史归一化——用全历史均值标准化某一天的量，
   就等于泄题。这是最隐蔽的一种前视。

### 15.3 部署形态与安全

产品形态是 **Web UI + 可部署到 Linux 云服务器**。

| 项 | 结论 |
|---|---|
| 前端 | Web UI（浏览器访问）。不做桌面客户端，不专门做移动端适配 |
| 后端 | 常驻 API 服务 |
| 部署 | 本地可跑 + 可部署到 Linux 云服务器，**同一套代码两条路径都成立** |
| 访问控制 | **必须认证登录**。虽然是单用户，但默认假定端口暴露在公网 |

**安全基线（公网暴露，这些不是可选项）**：

| 项 | 要求 |
|---|---|
| 认证 | 登录鉴权；密码用慢哈希；会话有有效期 |
| 暴力破解防护 | 登录失败限速 + 临时锁定 |
| 传输加密 | 全站 HTTPS，禁止明文回退 |
| 请求防护 | CSRF 防护、CSP |
| 数据库访问 | **参数化查询，禁止拼接 SQL** |
| 暴露面收敛 | 除 Web 端口外不对外开放端口；数据文件不可通过静态路径下载 |
| **训练数据备份** | 下单记录 / 会话 / 流水可定期备份，**并验证过能恢复** |

> ⚠️ **训练数据与行情数据必须分开对待**：行情数据丢了可以重下，
> **下单记录、训练会话、交易流水丢了就永久没了**——它们才是这个产品最有价值的东西。
> 所以训练数据备份是 P0，行情数据备份是 P2。

> 单用户 ≠ 低风险。公网 IP 上的服务会被持续扫描，**认证是必要项，不是加分项**。

### 15.4 AI 接入

|---|---|
| 挑选与叙述 | 从算法切好的候选区间池里挑题、写题目描述与考察点 |
| 归因解读 | 结算后解释「为什么这笔交易亏了」。**只解读数字，不重算数字** |
| 知识库整理 | 长程任务：把知识点整理成结构化条目（含 `detect_rule`） |

**绝不交给 AI 的事**：区间边界、收益率计算、结算结果、判断对错。
数字必须由算法算——这既是准确性要求，也是防前视的要求。

**已知风险与对策**：

| 风险 | 对策 |
|---|---|
| 模型侧前视（训练语料含该段行情） | 输入脱敏：不含真实日期与股票名，只给编号与时间偏移 |
| 幻觉（编造数字） | 结构化输出 + 字段校验，缺字段即丢弃；AI 只叙述不计算 |
| 供应商锁定 | 接口抽象 |
| 成本失控 | 批量预处理优先；知识库整理走批处理而非按需触发 |

### 15.5 非功能需求

| 类别 | 要求 |
|---|---|
| **性能（判断模式）** | 单题「观察 → 下单 → 结算 → 知识点匹配」全流程 ≤ 3 秒 |
| **性能（回放推进）** | 单次推进响应 ≤ 300 毫秒。前提：分钟数据按 `datetime` 建索引 |
| **性能（全股票快照）** | 单格快照 ≤ 1 秒，需预聚合 |
| **磁盘规划** | 按 **8 ~ 10 GB** 预留 |
| **首次初始化** | 全市场分钟数据下载是天级任务（40 ~ 200 小时），**必须支持断点续传** |
| **并发** | 单用户；但需明确 DuckDB **单写者约束** |
| **可观测性** | 有运行日志；同步任务、结算异常、匹配失败均可追溯 |
| **离线可用** | 数据同步完成后，日常练习不依赖外部数据源 |
| **可恢复** | 原始层永不修改，清洗层可随时从原始层重跑 |

## 17. 路线图

| 里程碑 | 目标 | 主要交付物 | 完成标志 |
|---|---|---|---|
| **M0 数据底座** | 把数据装进本地 / 服务器 | 数据同步脚本（含 21:00 定时任务 + 健康检查）、表结构、涨跌停预计算、git 仓库初始化 | 能查出任意股票任意日期的行情、复权价、涨跌停价；定时同步跑通且异常会告警 |
| **M1 单题闭环** | 先搭壳，再跑通一道题 | Web 服务骨架、**认证登录 + HTTPS**、**交易引擎**、下单界面、结算页 | 能从浏览器登录、手工指定一道题（含初始持仓）并**完成下单**，算出账户结果 |
| **M2 题目池与出题** | 从「手工出题」到「系统出题」 | 区间切分算法、题目池、随机抽题、题目初始状态生成 | 题目池 ≥ 10 万道，空仓型与持仓型均有，ID 可复现 |
| **M3 知识复盘** | 每次练习都有知识巩固 | 知识点库（批次 1 的 30 种）、匹配引擎、显著性打分、展示层 | 下单后能自动匹配、分层展示并高亮 K 线位置 |
| **M4 学习档案** | 看见自己的进步与偏差 | 练习记录、仓位分布统计、机会成本追踪 | 能按区间类型看到自己的仓位分布与账户收益 |
| **M5 时间回放** | 把时间推回去，连续交易 | 分钟数据接入（含断点续传）、推进引擎、**不复权口径 + 除权处理**、会话持久化、净值曲线 | 从指定日期逐格推进、完成买卖、**跨除权日净值正确**、能恢复会话并出复盘报告 |

**依赖关系**：M0 → M1 → M2 严格串行；M3 依赖 M1 的结算事件；M4 依赖 M2 的题目池；
**M5 依赖 M0（分钟数据）与 M1（交易引擎），可与 M2 ~ M4 并行推进。**

**M5 的排期建议**：**先做单股票模式**——一只票 10 年的分钟数据仅约 12 万行、即时加载，
不需要预下载全市场数据就能开发与使用。全股票模式等分钟数据下载完成（2 ~ 8 天）后再开。

**题目池规模的推导**：约 1000 只股票 × 每只约 100 个候选区间 ≈ 10 万道。

## 18. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | **免费数据源失效**（AkShare 尤其） | 数据补充能力下降 | 主数据源用稳定的 Baostock；AkShare 只做按需补充；原始层落地后即使接口失效也不影响已有数据 |
| R2 | **形态匹配规则写不准确** | 知识点命中错误，误导学习 | 先做批次 1 中规则明确的 30 种；**双关卡验收**（命中率 0.5%~5% + 抽样核对） |
| R3 | **知识点命中过多导致信息过载** | 用户不看，功能失效 | 数据层全留、展示层收敛（默认展开前 40%），按类别分组 |
| R4 | **陷入「技术上很酷但没用起来」** | 项目烂尾 | 先跑通 M1 单题闭环就自己用起来，不要一开始就追求全市场批量出题 |
| R5 | **收益率数字算错而不自知** | 整个产品失去意义 | 用 5 条红线做验证；结算逻辑写单元测试，用已知案例对拍 |
| R6 | **长周期投入导致半途而废** | 项目停滞 | 每个里程碑都能独立产生价值；M1 完成后就已经可用 |
| R7 | **分钟数据下载中断** | 回放出现数据空洞，净值曲线断裂 | 断点续传 + 每日失败清单重试 + 数据健康检查 |
| R8 | **额外数据源依赖** | 部分知识点无法实现 | G 批次中的龙虎榜等依赖 AkShare 且易失效。**这类知识点标 `detect_rule = null` 降级为仅可查，不阻塞主线** |
| R9 | **训练数据丢失** | 最珍贵的资产永久损毁 | 训练数据与行情数据分开备份，并**验证过能恢复**（P0 级） |
