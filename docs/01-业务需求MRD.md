## 1. 产品定位

### 1.1 一句话定义

> **复盘**：用真实历史数据当考题、用真实行情当判卷的 A 股决策训练平台。
> **把时间推回过去，用真金白银下单，让市场告诉你结果。**

两个训练模式，共用同一套交易与结算规则：

| 模式 | 一句话 | 训练什么 |
|---|---|---|
| **判断模式** | 给一段区间，在决策点下单，用之后的行情结算 | 单次决策质量、仓位管理 |
| **回放模式** | 把时间推回某天，逐格推进、连续交易 | 买入时机、持仓管理、盘感 |

两个模式的**唯一区别是推进粒度**（一个决策点 vs 逐格推进），
交易规则、成本模型、结算口径完全一致。

### 1.2 这是什么 / 不是什么

划这条界线是为了**防止功能蔓延**——每加一个功能前，先问它是否越界。

| 这是 | 这不是 |
|---|---|
| 历史决策训练工具 | 荐股软件 / 投资顾问 |
| 认知偏差的照妖镜 | 模拟炒股比赛 |
| 技术分析知识的实证工具 | 行情看盘软件 |
| 个人知识管理系统 | 交易执行系统 / 自动下单 |
| 数据驱动的复盘工具 | 社交 / 排行榜产品 |

**明确不做的事**（写死，避免以后动摇）：

- 不接入实盘账户、不做自动交易
- 不提供针对当前市场的买卖建议
- 不做实时行情、不做盘中提醒
- 不判定用户的判断「成功」或「失败」

### 1.3 设计哲学（三条不可动摇的原则）

1. **只给过去，不给未来。**
   用户在决策点上能看到的，只有决策点之前的数据。
   任何形式的前视污染都视为**产品缺陷**，不是「体验问题」。
2. **不判对错，只给事实。**
   输出收益率、超额收益、机会成本、最大回撤，但绝不说「你判断错了」。
   对错交给用户自己对照，避免产品替用户下结论。

   ⚠️ **这条对学习档案同样成立**：指标只给**比例数字与对照项**，
   **不使用「过度保守」「追高」「杀跌」这类形容词**。
   给事实和对照、不给结论——否则产品会变成另一种说教，与自身定位矛盾。（详见 7.2）
3. **逼近真实成本。**
   手续费、印花税、过户费、滑点、T+1、涨跌停无法成交、停牌，全部模拟。
   宁可结算结果难看，也不要一个「理论收益率」。

## 2. 背景与问题

### 2.1 要解决的四个问题

| # | 问题 | 现状的痛点 |
|---|---|---|
| 1 | **看盘软件只讲「发生了什么」** | 打开软件能看到全部走势，无法回到「当时只知道这些」的状态，因此永远训练不到真实决策能力 |
| 2 | **模拟炒股周期太长、样本太少** | 用实时行情模拟，一个决策要等一个月才能验证；练 20 次要一年多，学不到东西 |
| 3 | **人肉复盘带着后见之明** | 自己翻历史 K 线时，眼睛已经看到了后面的走势，无法排除前视偏差，复盘结论不可靠 |
| 4 | **技术分析知识停留在术语层面** | 学了一堆形态名称，但从没验证过「这个形态在 A 股到底有没有用」 |

### 2.2 为什么现在可行

- **数据可得**：Baostock 免费提供全 A 股含退市股的完整历史日线（含复权因子），
  这是过去需要付费才能拿到的数据。（详见 00 号文档第 11 节）
- **算力足够**：全历史约 4500 万行日线，Parquet 压缩后不到 1 GB，
  DuckDB 秒级查询，不需要任何分布式方案。
- **无合规负担**：仅个人学习自用，不对外发布、不收费、不提供投资建议。

### 2.3 明确排除的做法

- 不做实时行情：本项目是历史训练，实时数据既贵又无用
- **不做移动端原生 App**：先做 Web UI（浏览器访问，手机也能开但**不专门做移动适配**），
  避免过早背上跨端成本
- 不做深度学习模型：数据量与验证成本都不划算，先用规则策略

## 3. 目标用户与使用场景

### 3.1 用户画像

| 维度 | 描述 |
|---|---|
| 身份 | 个人投资者 / 技术爱好者。本项目目前只有 1 位用户（产品作者本人） |
| 能力 | 会写代码，能自己动手改；懂基本交易规则；技术分析知其名不知其实证 |
| 约束 | 每天可投入 10~30 分钟；周末可投入 1~2 小时 |
| 设备 | **浏览器访问为主**（本地开发用 macOS；生产部署在 Linux 云服务器） |
| 痛点 | 缺乏结构化练习；没有客观反馈；技术知识无法验证 |

### 3.2 典型场景

| # | 场景 | 期望行为 | 成功标志 |
|---|---|---|---|
| S1 | **碎片时间刷题** | 打开软件，做 3~5 道随机题 | 单题全流程 ≤ 2 分钟 |
| S2 | **周末系统性练习某个板块** | 按行业 / 板块筛选标的，连续练 20 道同类题 | 能按条件筛题并批量练习 |
| S3 | **验证一个技术形态** | 想确认「早晨之星到底有没有用」，直接查该知识点的全历史统计 | 能看到出现次数、上涨概率、样本量 |
| S4 | **看清自己的判断偏差** | 查看学习档案：什么行情类型下判断得准，什么情况下总是错 | 按区间类型分组的准确率与收益分布 |

### 3.3 使用频率预期

- 日常：每天 3~10 题（碎片时间）
- 深度：每周 1 次 20~50 题（周末）
- 查询：需要时随时翻知识库与统计

## 4. 产品目标与衡量

### 4.1 北极星指标

> **累计完成的「有效练习」数量**（同一题重复练习只计首次）

选它而不是「收益率」的理由：本产品是学习工具，衡量的是**练习量与练习质量**，
不是赚钱能力。用收益率当指标会诱导用户去追高风险题目，方向就歪了。

**关于「重复练习」的定位**（回答一个容易含糊的点）：

| 类型 | 是否计入北极星 | 说明 |
|---|---|---|
| 首次练习 | ✅ 计入 | 有效样本，进入学习档案统计 |
| 重复练习 | ❌ 不计入 | **但允许做，且完整记录**。用途是「复习」，不进成绩分母 |

两类记录都不删除。重复练习的价值是**巩固**，不是刷成绩——
因此重新作答同一道题**不会提升任何统计指标**，从机制上避免自我刷分。

### 4.2 阶段性目标

| 阶段 | 目标 | 可验证的完成标志 |
|---|---|---|
| M1 后 | 闭环跑通，能独立做完一道题 | 能登录、在决策点**实际下单**、看到结算与账户结果 |
| M2 后 | 题目池有货，能连续练习 | 题目池 ≥ 10 万道（推导见 FR-2.3），可随机抽题 |
| M3 后 | 每次练习都有知识巩固 | 下单后能自动匹配并展示知识点 |
| M4 后 | 能看见自己的进步与偏差 | 学习档案按区间类型 / 知识点给出分组统计 |
| M5 后 | 能把时间推回去连续交易 | 单股票模式可用；能恢复会话并出复盘报告 |

### 4.3 明确不追求的指标

- 不追求收益率最大化（这是训练工具，不是策略）
- 不追求用户数、留存、活跃（个人自用）
- 不追求形态识别覆盖率 100%（**批次 1 的 30 种**就够启动，见 `02-知识点库建设计划.md`）

## 5. 核心概念与术语表

| 术语 | 定义 |
|---|---|
| **区间** | 一段连续的历史行情，有明确的起止日期。用户要在这段区间末做出判断 |
| **决策点（T）** | 区间的最后一个交易日。用户只能看到 T 及之前的数据 |
| **结算窗口** | 决策点之后的验证期，默认 20 个交易日 |
| **题目（Question）** | 一道练习的最小单位 = 股票 + 区间 + 类型标签 + 结算参数 |
| **判断模式** | 用户在一个决策点**实际下单**，用之后的行情结算（主模式） |
| **判卷模式** | 系统给出**仓位建议**，用户评判建议对不对（判断模式的辅助分支） |
| **机会成本** | 标的实际收益 − 账户收益。衡量「错过了多少 / 躲过了多少」 |
| **超额收益** | 账户收益 − 基准（沪深300）收益 |
| **时点标的池** | 回答「那一天在市的股票有哪些」，而非「今天在市的股票」 |
| **知识点命中** | 算法在区间内检测到某个技术形态出现（同一知识点可多次命中） |
| **显著性分** | 知识点命中的可信程度打分，用于分层展示 |
| **技术工具** | 观察时可叠加的指标：均线、成交量、MACD、KDJ、BOLL |
| **时间回放模式** | 把时间推回某一天、逐格推进并真实买卖的训练模式 |
| **推进粒度** | 回放模式每次前进的时间长度，默认 5 分钟 |
| **训练会话** | 一次回放训练从开始到结束的完整过程（资金、持仓、交易记录、当前时刻） |
| **净值曲线** | 回放模式下总资产随时间的变化，是该模式的结果呈现 |
| **盘感** | 全股票模式训练的目标：在几千只票中快速识别机会的能力 |
| **下单** | 用户的实际交易操作：买入 / 卖出 + 股数（取代原来的三选一判断） |
| **持仓** | 当前持有的股票与成本。**有持仓时，「持有」与「卖出」才成为不同动作** |
| **仓位** | 持仓市值 ÷ 总资产。**仓位大小本身就是本产品的训练内容之一** |
| **交易引擎** | 两个模式共用的下单 / 成交 / 持仓 / 成本 / 净值计算模块 |
| **题目初始状态** | 每道题指定的起始持仓：空仓型 或 持仓型（N 股 @ 成本 Y） |
| **快照冻结** | 结算时锁定当时的复权因子与费率，保证历史成绩日后不被改写 |

## 6. 核心业务流程

本项目有**两个训练模式**。它们的**交易规则、成本模型、结算口径完全一致**，
唯一区别是**推进粒度**：判断模式一个决策点，回放模式逐格推进。

### 6.1 区间判断模式 · 主流程（七步）

1. **选股** → 从时点标的池中选一只股票（或系统随机）
2. **出题** → 系统从题目池中切出若干候选区间供选择
3. **用户选题** → 选定一个区间作为本次考题
4. **观察** → 界面只显示决策点之前的数据；可叠加技术工具辅助判断
5. **下单** → **实际的买入 / 卖出操作**（含股数与快捷仓位按钮）。
   有持仓时可加仓、减仓、清仓；无持仓时可建仓或观望
6. **真实结算** → 按决策点之后的真实行情计算账户结果与各项指标
7. **知识复盘** → 匹配本区间出现的知识点并弹出，供巩固记忆

> **与原设计的关键区别**：第 5 步从「三选一（买入 / 持有 / 卖出）」改为**真实下单**。
> 这样「买多少」也成为训练内容，且持仓型题目可以考察「该不该卖」。

### 6.2 区间判断模式 · 分支：判卷模式

在步骤 5 前插入一步：系统给出**仓位建议**（如「建议加仓至 60%」），
用户评判这个建议对不对，再走结算。

### 6.3 时间回放模式 · 主流程

1. **设定起点** → 选一只股票（单股票模式）或选一个日期（全股票模式），
   同时设定推进粒度与结束条件
2. **推进时间** → 自动推进（像看盘）或手动推进（按一次走一格）。
   **只能前进，不能后退**
3. **观察决策** → 看当前时刻的分时、K 线、技术指标；全股票模式还可看全市场快照
4. **下单** → 买入 / 卖出 / 加仓 / 减仓。成交价按规则取**下一格**的价格
5. **继续推进** → 持仓随行情波动，净值实时更新
6. **结束** → 到达预设结束日，或用户主动结束；不设结束则一直玩到数据末尾
7. **复盘报告** → 净值曲线、交易明细、交易统计、对比沪深300

### 6.4 异常流程

| 异常 | 处理 |
|---|---|
| 区间内该股停牌 | 结算时跳过停牌日，按复牌首日可成交价处理 |
| 结算窗口内该股退市 | 按退市整理期最后成交价强制平仓，并在结算页标记该题 |
| 决策点次日一字涨停（无法买入） | 顺延到下一个可成交日；窗口内始终无法成交则标记「未成交」，该笔不成交 |
| 决策点次日一字跌停（无法卖出） | 同上，顺延 |
| 数据缺失 / 交易日历异常 | 该题作废，不进入题目池 |
| 结算窗口不足 20 个交易日 | 该题暂不出题 |
| **回放中持仓股停牌** | 该股暂停交易，净值按停牌前价格冻结，推进不停 |
| **回放中持仓股退市** | 按退市整理期最后成交价强制平仓，并在会话中标记 |
| **回放会话中断（关浏览器）** | 会话状态已持久化，下次恢复到最后推进到的时刻 |
| **用户尝试后退时间** | 服务端无此接口，请求直接失败 |

## 7. 功能需求清单

### 7.0 优先级定义（v1.3 重定义）

上一版把「P0 = MVP 必须」，结果 85 条需求里标了 **57 条 P0（67%）**，
优先级完全失去排序作用——等于没有优先级。本次重定义：

| 级别 | 含义 | 数量约束 |
|---|---|---|

### 7.1 难度量化定义

难度分**只用于筛选与统计，不向用户展示**——这条决定了能不能用全历史数据标定。

拆成两个分：

| 分 | 用什么算 | 用途 |
|---|---|---|
| **事前难度** | 只用决策点**之前**的信息 | 筛题（例如「来 10 道难题」） |
| **事后难度** | 事前难度 + 结算窗口内的实际走势 | 统计（例如「我在难题上的表现是否更差」） |

**事前难度的三个成分**（可解释加权，便于事后调参）：

| 成分 | 含义 | 直觉 |
|---|---|---|
| 区间波动率 | 区间内日收益标准差 | 越波动越难读 |
| 信号冲突度 | 命中的看涨知识点数与看跌知识点数的接近程度 | 信号打架时最难判断 |
| 区间振幅 | 区间内最高最低价之差 | 走了很远之后，位置判断更难 |

**事后难度**追加一个成分：**结果显著度** = 结算窗口内涨跌幅的绝对值。
幅度越小越难判断——因为方向本来就不明确。

> 因为难度分**不展示给用户**，可以用全历史分位数做归一化标定，不构成泄题。
> 将来若要展示难度，**必须改用截止决策点的历史分位数**，否则是前视偏差。

### 7.2 学习档案指标定义

设计目标：**呈现事实与对照，让用户自己看出模式**——而不是替用户下结论。

> ⚠️ 这与 1.3 设计哲学第 2 条一致：**给数字和对照，不给形容词。**
> 不使用「过度保守」「追高」「杀跌」这类评判性措辞。

| 指标 | 定义 | 呈现方式 |
|---|---|---|
| 累计有效练习数 | 按模式 / 区间类型分组计数，重复练习只计首次 | 数字 |
| 平均仓位 | 每笔练习的平均仓位比，按区间类型分组 | 数字 |
| **仓位方向匹配度** | 上涨区间的平均仓位 − 下跌区间的平均仓位 | **两个数字并列**，差值仅作参考 |
| 账户收益率 | 账户视角收益率（含全部成本） | 数字 |
| 相对沪深300 收益 | 账户收益率 − 沪深300 同期收益 | 数字 |
| **机会成本** | 标的收益 − 账户收益 | **必须与上一行配对展示** |
| 最大回撤 | 持有期间最深浮亏 | 数字 |
| 交易频率 | 平均每笔练习的下单次数 | 数字 |
| **持仓型题目的选择分布** | 加仓 / 不动 / 减仓 / 清仓 各占多少 | **四个比例并列** |
| 各类行情下的仓位分布 | 上涨 / 下跌 / 震荡 区间的平均仓位 | 三个数字并列 |
| 知识复盘查看率 | 下单后查看知识点的比例 | 数字 |
| 知识点学习效果 | 看过某知识点后，同类题目的表现变化 | 数字 |

**呈现原则（三条）**：

1. **不出现形容词。** 「空仓比例 62%」是事实，「过度保守」是评判——只给前者。
2. **必须给对照。** 单独一个 62% 没有意义，要和「同期标的上行概率 51%」并列才有意义。
3. **让用户自己下结论。** 产品的职责是把镜子擦亮，不是告诉用户长得怎么样。

> 这些才是本产品的差异化价值。收益率谁都能算，
> **能照出你自己的行为模式**，才是训练工具的意义。

> ⚠️ **指标随本次改造已重写**：原来的「判断方向准确率」建立在三选一之上，
> 现在改为下单制，直接看**仓位变化方向**更准确。
> 原来的「空仓偏好度」等三项因措辞带评判，已改为中性的仓位分布统计。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| **形态** | Web UI（浏览器访问）；不做桌面客户端，**不专门做移动端适配** |
| **部署** | 本地可跑 + 可部署到 Linux 云服务器，**同一套代码两条路径都成立** |
| **安全** | 必须认证登录；全站 HTTPS；详见 FR-8 |
| **时区** | 定时任务显式指定时区（北京时间 **21:00**），**不依赖服务器本地时区** |
| **性能（判断模式）** | 单题「观察 → 下单 → 结算 → 知识点匹配」全流程 ≤ 3 秒 |
| **性能（回放推进）** | 单次推进响应 ≤ 300 毫秒。**前提**：分钟数据按 `datetime` 建索引，不做全表扫描 |
| **性能（全股票快照）** | 单格快照 ≤ 1 秒（约 5400 只股票的当前格行情），需预聚合 |
| **数据规模** | 日线约 4500 万行 / < 1 GB；**5 分钟线（10 年）约 7.2 亿行 / 4~7 GB** |
| **磁盘规划** | 按 **8~10 GB** 预留（含索引与临时空间）——**不是原来估的 1 GB** |
| **首次初始化** | 全市场分钟数据下载是**天级任务**（约 40~200 小时），**必须支持断点续传与失败重试** |
| **并发** | 单用户场景，但需明确 **DuckDB 单写者约束**：同步任务与 API 服务不可同时写 |
| **可观测性** | 有运行日志；同步任务、结算异常、匹配失败均可追溯（FR-7.6） |
| **离线可用** | 数据同步完成后，日常练习不依赖外部数据源 |
| **可恢复** | 原始层数据永不修改，清洗层可随时从原始层重跑 |
| **依赖** | 只用免费数据源，不引入需要付费订阅的组件 |

## 9. 质量红线（不可妥协）

这四条是本项目区别于「看起来像那么回事」的关键。
**每条都给判定方法**——只写要求不算数。

| # | 红线 | 要求 | **怎么验证做对了** |
|---|---|---|---|
| 1 | **前视偏差** | 用户与 AI 在任何环节都拿不到决策点之后的数据 | ①抓包检查下单接口，返回数据 `max(date) ≤ end_date`；②指标曲线末点日期 ≤ 决策点；③下单前界面无任何知识点；④回放模式只能看 `dt ≤ 当前时刻`（详见 00 号文档第 9 节） |
| 2 | **价格口径** | **判断模式**：展示前复权、算收益后复权。**回放模式**：展示与成交**一律不复权** | ①取一只多次分红的银行股，判断模式手工核对收益率，应与不复权算法**不相等**且差异方向合理；②回放模式跨除权日时 **净值不出现凭空暴跌**，且股数与现金按送股 / 分红正确调整 |
| 3 | **成交可行性** | 无法成交的情况必须真实反映 | 找一只真实一字板股票，验证该日买入被拒绝并正确顺延 |
| 4 | **幸存者偏差** | 标的池含退市股，按「当时在市」过滤 | ①数据库中能查到已知退市股的历史；②指定一个历史日期，标的池中**不含**该日尚未上市的股票 |
| 5 | **结果可复现** | 历史成绩不因数据更新被改写 | 记录一笔结算结果，更新复权因子后重算，**数字必须完全一致**（依赖 FR-4.6 快照冻结） |

> 第 5 条是本次评审新增：复权因子会随新的分红除权重算，
> 若不冻结快照，用户三个月前那笔练习的收益率**今天重算会变**。

## 10. 路线图

| 里程碑 | 目标 | 主要交付物 | 完成标志 |
|---|---|---|---|
| **M0 数据底座** | 把数据装进本地 / 服务器 | 数据同步脚本（含 **21:00** 定时任务 + 健康检查）、表结构、涨跌停预计算、git 仓库初始化 | 能查出任意股票任意日期的行情、复权价、涨跌停价；定时同步跑通且异常会告警 |
| **M1 单题闭环** | 先搭壳，再跑通一道题 | Web 服务骨架、**认证登录 + HTTPS**、**交易引擎**、下单界面、结算页 | 能从浏览器登录、**手工指定一道题（含初始持仓）并完成下单**，算出账户结果 |
| **M2 题目池与出题** | 从「手工出题」到「系统出题」 | 区间切分算法、题目池、随机抽题、题目初始状态生成 | 题目池 ≥ 10 万道，空仓型与持仓型均有，ID 可复现 |
| **M3 知识复盘** | 每次练习都有知识巩固 | 知识点库（批次 1 的 30 种）、匹配引擎、显著性打分、展示层 | 下单后能自动匹配、分层展示并高亮 K 线位置 |
| **M4 学习档案** | 看见自己的进步与偏差 | 练习记录、仓位分布统计、机会成本追踪 | 能按区间类型看到自己的仓位分布与账户收益 |
| **M5 时间回放** | 把时间推回去，连续交易 | 分钟数据接入（含断点续传）、推进引擎、**不复权口径 + 除权处理**、会话持久化、净值曲线 | 从指定日期逐格推进、完成买卖、**跨除权日净值正确**、能恢复会话并出复盘报告 |

**依赖关系**：M0 → M1 → M2 严格串行；M3 依赖 M1 的结算事件；M4 依赖 M2 的题目池；
**M5 依赖 M0（分钟数据）与 M1（交易引擎），可与 M2 ~ M4 并行推进。**

**M5 的排期建议**：**先做单股票模式**——一只票 10 年的分钟数据仅约 12 万行、即时加载，
不需要预下载全市场数据就能开发与使用。

**全股票模式要等**：全市场分钟数据下载是一个 **40 ~ 200 小时（2 ~ 8 天）**的天级任务，
且过程中断在所难免。所以 M5 分两步上线，单股票模式不必等这个下载。

## 11. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | **免费数据源失效**（AkShare 尤其） | 数据补充能力下降 | 主数据源用稳定的 Baostock；AkShare 只做按需补充；原始层落地后即使接口失效也不影响已有数据 |
| R2 | **形态匹配规则写不准确** | 知识点命中错误，误导学习 | 先做批次 1 中规则明确的 30 种；**双关卡验收**：日命中率落在 0.5%~5% + 抽样肉眼核对 10 例（见 `02` 号文档） |
| R3 | **知识点命中过多导致信息过载** | 用户不看，功能失效 | 数据层全留、展示层收敛（默认展开前 40%），按类别分组 |
| R4 | **陷入「技术上很酷但没用起来」** | 项目烂尾 | 先跑通 M1 单题闭环就自己用起来，不要一开始就追求全市场批量出题 |
| R5 | **收益率数字算错而不自知** | 整个产品失去意义 | 用第 9 节的 **5 条红线**做验证；结算逻辑写单元测试，用已知案例对拍 |
| R6 | **长周期投入导致半途而废** | 项目停滞 | 每个里程碑都能独立产生价值；M1 完成后就已经可用 |
| R7 | **分钟数据下载中断** | 回放出现数据空洞，净值曲线断裂 | **断点续传 + 每日失败清单重试 + 数据健康检查**（FR-7.1） |
| R8 | **额外数据源依赖** | 部分知识点无法实现 | G 批次「成交与资金」中的龙虎榜等依赖 AkShare 且易失效。**这类知识点标 `detect_rule = null` 降级为仅可查，不阻塞主线** |
| R9 | **训练数据丢失** | 最珍贵的资产永久损毁 | 训练数据与行情数据分开备份，并**验证过能恢复**（FR-8.7，P0 级） |
