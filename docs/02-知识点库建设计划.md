## 1. 目标与三条原则

用户决策：知识点**要齐全，不设数量上限**，并作为独立的长程任务持续推进。

| 原则 | 含义 | 如果违反了会怎样 |
|---|---|---|
| **知识点是数据，不是代码** | `detect_rule` 用 JSON DSL 描述，新增知识点 = 插一行数据 | 每加一个形态都要改代码、测代码、发版，半年后引擎变成一堆 if-else |
| **引擎只认原语** | 引擎实现一组通用特征与算子；表达不了的新形态 → **扩展原语**，不给单个知识点开特例 | 引擎腐化，规则越加越乱，无法维护 |
| **每条规则必须可验证** | 有客观的判定标准（命中率区间 + 抽样肉眼核对） | 规则写完没人知道对不对，知识点统计全是噪声 |

## 2. 数据模型

```
dim_knowledge
├── kb_id              知识 ID（稳定不变，用作外键）
├── name               名称，如「早晨之星」
├── alias              别名，如「晨星」「希望之星」
├── category           一级分类（见第 5 节）
├── sub_category       二级分类
├── definition         一句话定义（≤ 50 字）
├── detect_rule        可量化识别规则（JSON DSL，可为 null）
├── detect_type        point / persistent / null
├── window_size        判定窗口长度（根）
├── min_confirm_bars   最少确认根数
├── base_weight        基础权重（用于显著性打分）
├── signal_direction   bullish / bearish / neutral
├── position_hint      常见位置：top / bottom / middle / any
├── meaning            含义与用法（怎么读它）
├── pitfalls           常见误用（≥ 2 条）
├── diagram_ref        示意图引用（程序化生成，见第 7 节）
├── related            [相关知识点 kb_id]
├── sample_min         统计最小样本量（默认 100）
├── version            条目版本号
└── enabled            是否启用（支持灰度上线 / 单独下架）
```

**配套结果表**（已定义于 00 号文档 12.8）：

```
fact_knowledge_match
├── match_id, kb_id, code
├── start_date / end_date      命中区间（point 型为同一天）
├── confidence                 规则匹配度
├── severity_score             显著性分
└── detail                     JSON，存命中细节
```

## 3. `detect_rule` DSL 规范

### 3.1 设计思路

规则**不写公式**，只做「读取预定义特征 → 比较 → 组合」。
所有计算（均线、量比、相关系数…）都由**引擎预计算成特征列**，
规则只引用特征名。

好处：

- 规则短、可读、可复用
- 特征只算一次，规则再多也不会变慢
- 调参就是改 `value`，不动结构

### 3.2 特征原语

**单根 K 线特征**（用 `bar` 做相对索引，`0` = 当前根，`-1` = 前一根）

| 字段 | 含义 |
|---|---|
| `open` `high` `low` `close` | 价格 |
| `volume` `amount` | 成交量 / 成交额 |
| `pct_chg` | 涨跌幅 % |
| `body` | 实体大小 = \|close − open\| |
| `body_ratio` | 实体 / 振幅，0~1。越小越像十字星 |
| `upper_shadow_ratio` / `lower_shadow_ratio` | 上 / 下影线占振幅比 |
| `direction` | `up` / `down` / `flat` |
| `is_limit_up` / `is_limit_down` | 是否收在涨停 / 跌停板 |
| `volume_ratio` | 量比 = 当日量 / 近 5 日均量 |
| `turnover` | 换手率 |

**序列特征**（需要窗口 `window`）

| 字段 | 含义 |
|---|---|
| `ma(n)` | n 日均线 |
| `close_vs_ma(n)` | 收盘价相对 n 日均线偏离 % |
| `ma_slope(n, k)` | n 日均线在 k 日内的斜率 |
| `highest(n)` / `lowest(n)` | 近 n 日最高 / 最低价 |
| `position_in_range(n)` | 当前价在近 n 日区间中的位置，0~1 |
| `volatility(n)` | 近 n 日收益率标准差 |
| `vol_ma(n)` | 近 n 日均量 |
| `corr_price_volume(n)` | 近 n 日价量相关系数 |

### 3.3 算子

| 类别 | 写法 |
|---|---|
| 比较 | `"op": ">"` / `>=` / `<` / `<=` / `==` / `!=` |
| 区间 | `"op": "between", "value": [a, b]` |
| 引用其他根 | `"value_ref": "close@-3"`（第 3 根前的收盘价） |
| 引用序列特征 | `"value_ref": "highest(20)@-5"` |
| 逻辑组合 | `all_of`（全满足）/ `any_of`（任一）/ `none_of`（全不满足） |
| 计数 | `"count_of": { ...条件..., "min_count": 2 }`（满足条件的根数 ≥ k） |

### 3.4 两个完整示例

**示例 A：早晨之星（point 型，逐根滑窗）**

```json
{
  "kb_id": "kc_morning_star",
  "detect_type": "point",
  "window_size": 3,
  "anchor": -1,
  "conditions": {
    "all_of": [
      { "field": "direction",  "bar": -3, "op": "==", "value": "down" },
      { "field": "body_ratio", "bar": -3, "op": "<=", "value": 0.5 },
      { "field": "body_ratio", "bar": -2, "op": "<=", "value": 0.3 },
      { "field": "low",        "bar": -2, "op": "<",  "value_ref": "low@-3" },
      { "field": "direction",  "bar": -1, "op": "==", "value": "up" },
      { "field": "close",      "bar": -1, "op": ">",  "value_ref": "close@-3" }
    ]
  },
  "min_confirm_bars": 0,
  "signal_direction": "bullish"
}
```

读法：前三根依次是「中阴线 → 小实体（向下跳空）→ 中阳线，
且阳线收盘价涨回第一根收盘价之上」。

**示例 B：顶背离（persistent 型，区间状态）**

```json
{
  "kb_id": "vp_bearish_divergence",
  "detect_type": "persistent",
  "window_size": 20,
  "duration_bars": 5,
  "conditions": {
    "all_of": [
      { "field": "close",   "bar": 0, "op": ">=", "value_ref": "highest(20)@-5" },
      { "field": "volume",  "bar": 0, "op": "<",  "value_ref": "volume@-5" },
      { "field": "corr_price_volume", "window": 20, "op": "<", "value": 0 }
    ]
  },
  "signal_direction": "bearish"
}
```

读法：价格创近 20 日新高，但成交量低于前一个高点时的量，
且近 20 日价量呈负相关。返回的是**一段成立区间**，不是一个点。

## 4. 规则的质量标准（客观可验证）

规则写完不能靠"看着像"。每条规则必须过两道关：

### 4.1 第一关：命中率落在合理区间

跑全 A 股全历史，统计该规则的**日命中率**：

| 日命中率 | 判断 | 处理 |
|---|---|---|
| > 10% | 太松，没有区分度 | 收紧条件 |
| **0.5% ~ 5%** | ✅ 合理区间 | 通过 |
| < 0.1% | 太严，样本不足，统计无意义 | 放宽条件 |
| = 0 | 规则写错了 | 排查特征或逻辑 |

### 4.2 第二关：抽样肉眼核对

随机抽 10 个命中样本，人工确认是否符合形态的教科书定义。
**这关不能省**——命中率只是数量指标，不保证质量。

两条都过了，才允许 `enabled = true` 入职。

## 6. 建设批次与流程

### 6.1 批次规划

分批不是砍数量，而是**按"规则明确度"排序**——先做标准清晰、容易校准的。

| 批次 | 内容 | 数量 | 为什么这个顺序 |
|---|---|---|---|
| **批次 1** | A 单根 K 线 + B K 线组合 | 30 | 判定规则教科书明确，先跑通「规则 → 匹配 → 展示 → 统计」全链路 |
| **批次 2** | E 均线系统 + F 技术指标 | 26 | 纯数值计算，规则简单，命中率容易校准 |
| **批次 3** | D 量价关系 | 14 | 需要价量联合判断，略复杂 |
| **批次 4** | C 趋势与结构 | 15 | 最复杂，涉及区间级状态判定，放后面 |
| **批次 5** | G 成交与资金 | 8 | 部分需要额外数据源（龙虎榜） |
| **批次 6** | H 理论型 | 5 | 只入知识库，不做检测 |

### 6.2 每个知识点的处理流程

```
① 起草（AI）
   产出字段完整条目：定义 / 识别特征 / 含义 / 位置 / 常见误用 / 关联
        ↓
② 规则写作（AI）
   按 DSL 规范写出 detect_rule 初稿
        ↓
③ 命中率校准（算法）
   跑全历史，看日命中率是否落在 0.5%~5%，不在则调参
        ↓
④ 抽样核对（人工 or AI 复核）
   随机抽 10 个命中样本，确认符合教科书定义
        ↓
⑤ 入职
   写入 dim_knowledge，enabled = true
```

**第 ③④ 步是这套流程的价值所在**——它让"知识点质量"变成一个可测量的东西，
而不是"感觉写得挺对"。

## 7. 示意图的生成方式

建议**程序化生成**，不要手工画：

- 每个知识点给一段**合成的 OHLC 序列**（教科书形态的标准样例）
- 用同一套渲染代码画出 K 线示意图
- 优点：批量可做、风格统一、且**和 detect_rule 天然一致**
  （因为标准样例本身就应该被规则命中——顺便成了一条测试用例）

这条同时解决了一个隐含需求：**每个知识点都自带一个测试样本**。

## 9. 与其他模块的接口

| 依赖 | 关系 |
|---|---|
| **匹配引擎** | 读取本库的 `detect_rule`，按 `detect_type` 路由到 point / persistent 检测器 |
| **显著性打分** | 用本库的 `base_weight` + 命中时的 strictness 等特征算分（见 00 号文档 12.5） |
| **全历史胜率统计** | 用同一套检测器在全历史上跑，命中点接"未来 20 日收益" |
| **难度量化** | 「信号冲突度」成分需要本库的 `signal_direction` 字段（见 01 号文档 7.1） |
| **知识复盘展示** | 用 `category` 分组、`severity_score` 排序、`diagram_ref` 画图 |

**关键约束**：`signal_direction` 字段必须准确。
难度量化与知识点配平（历史遗留）都依赖它，标错了会连带出问题。
